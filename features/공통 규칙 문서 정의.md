### 1. 데이터팀이 하는 일

원본 기록은 길이가 제각각인 숫자 목록이다(패킷 50~10,000개). 데이터팀은 기록 하나를 **항상 같은 110개의 숫자(특징)**로 요약해 표(CSV)로 만든다. 모델팀은 이 표를 보고 어떤 사이트에 접속한 기록인지 맞히는 모델을 학습한다.

```
pkl 파일 로드
  → 기록마다 ID·라벨 부여
  → 시각·방향 분리
  → (조건에 따라) 앞부분 제거
  → 110개 특징 계산
  → CSV 저장
```

- 하나의 Colab 노트북에서 위 과정을 순서대로 실행한다.
- 실행하는 사람은 **맨 위 설정 칸에서 파일 종류와 제거 조건만** 바꾼다.

#### 기록 ID

모든 기록에 고유 ID를 붙인다. 모델링 시 결과를 원본 기록으로 되짚어 갈 수 있게 하기 위함이다.

| 데이터 | 형식 | 예시 |
| --- | --- | --- |
| mon | mon_p페이지번호_s접속번호 | mon_p017_s05 (17번 페이지의 6번째 접속) |
| unmon | unmon10k_순번 / unmon3k_순번 | unmon10k_00042 |

#### 라벨

- mon: 페이지 번호 ÷ 10의 몫 (0~94번 사이트)
- unmon: -1

### 3. 방향과 시각

| 항목 | 규칙 |
| --- | --- |
| 방향 | 원본 값이 **양수면 송신(+1)**, **0 이하면 수신(-1)** (제공 코드와 같은 기준) |
| 시각 | 원본 값의 절댓값(초) |

```
원본:  [0.0,  -0.14,  0.14]
방향:  [수신,  수신,  송신]
시각:  [0.0,   0.14,  0.14]
```

> 모든 기록의 첫 값은 0.0이므로 첫 패킷은 수신으로 처리된다.
>

### 4. 앞부분 제거 조건

| 조건 | 내용 |
| --- | --- |
| trim0 | 원본 그대로 |
| trim10 | 앞 10개 패킷 제거 |
| trim20 | 앞 20개 패킷 제거 |
- **이유**: 기록 초반이 웹사이트 특성이 아니라 수집 절차의 흔적일 가능성을 open-world에서 검증하기 위함이다(제안서 6-4 ②).
- **방법**: 앞 N개를 지운 뒤, 남은 첫 패킷의 시각이 0이 되도록 모든 시각에서 그 값을 뺀다. 방향은 그대로 둔다.

```
제거 후 남은 시각: [0.75, 0.80, 1.20]
→ 다시 맞춘 시각:  [0.00, 0.05, 0.45]
```

- 모든 기록이 50개 이상이므로 20개를 지워도 30개 이상 남는다.

### 6. 특징 열 이름

정의서와 코드에서 같은 이름을 쓰기 위해 **"그룹번호_내용" 형식의 영어 소문자**로 통일한다.

#### Feature 110개 전체 목록

> **기본 용어**
> 
> - **송신(↑)**: 내가 서버로 보낸 패킷 (원본 값이 양수)
> - **수신(↓)**: 서버에서 내가 받은 패킷 (원본 값이 0 이하)
> - **위치**: 기록 안에서 몇 번째 패킷인지 (0번부터 셈)
> - **묶음(버스트)**: 같은 방향이 연달아 이어지는 덩어리 (예: ↓↓↓ = 길이 3인 수신 묶음)
> - **간격(iat)**: 패킷과 패킷 사이의 시간 차이(초). iat = Inter-Arrival Time
> - **표준편차(std)**: 값들이 평균에서 얼마나 퍼져 있는지. 클수록 들쑥날쑥함
> - **중앙값(median, q50)**: 값을 크기순으로 줄 세웠을 때 한가운데 값
> - **25% 백분위수(q25)**: 크기순으로 줄 세웠을 때 아래에서 25% 위치의 값 (q75는 75% 위치)

### 7. 그룹별 계산 기준

#### 공통

- 패킷 위치는 **0부터** 센다 (첫 패킷 = 0번).

#### 그룹 2. 구간별 송신 수

- 기록을 앞에서부터 20·50·100개씩 나눠 구간마다 송신 수를 센다.
- <u>**마지막 불완전 구간은 기본적으로 제외한다.**</u>

```
패킷 45개를 20개씩 나누면:
[1~20번] [21~40번] [41~45번]
  20개      20개      5개 ← 불완전 구간 → 제외
```

- 포함하는 버전도 코드 설정으로 만들 수 있게 하여, 모델팀이 검증으로 비교할 수 있게 한다.
- 완전한 구간이 하나도 없는 짧은 기록(예: 100개 단위인데 기록이 80개)은 **기록 전체를 하나의 구간**으로 계산한다.

#### 그룹 3. 연속 묶음

- 같은 방향이 이어지는 구간을 묶음 하나로 본다.

```
수신 수신 송신 수신 → [수신2] [송신1] [수신1] → 묶음 3개
```

- 길이별 묶음 수는 **송신·수신 묶음을 모두 합쳐서** 센다.

#### 그룹 4. 초반·후반 비율

- 기록이 30개 또는 100개보다 짧으면 **있는 패킷만으로** 계산한다.

#### 그룹 5. 시간·속도

| 항목 | 계산 기준 |
| --- | --- |
| 지속 시간 | 마지막 시각 − 첫 시각 |
| 1초 구간별 패킷 수 | 0초부터 마지막 시각까지 1초 단위로 나누고, **패킷이 없는 구간도 0으로 포함** |
| 상대 도착 시점 | (해당 패킷 시각 − 첫 시각) ÷ 지속 시간. 25% 시점 = 전체 중 25%번째로 도착한 패킷 기준 |
| 시간 간격 | 바로 이전 패킷과의 시각 차이. 송신 간격은 송신끼리, 수신 간격은 수신끼리 |
| 사분위수 | 25%·50%·75% 백분위수 |

#### 그룹 6. 누적 흐름

- 송신 +1, 수신 -1을 처음부터 차례로 더한다.
- 처음부터 끝까지 **같은 간격으로 50개 지점**을 잡고, 지점이 패킷 사이에 걸리면 앞뒤 값을 비례해서 채운다(보간).
- 100개 지점 버전도 같은 방식이다.

### 8. 계산할 수 없는 경우의 대체값

> <u>**계산이 불가능한 경우는 모두 0으로 채우고, 해당 기록 수를 리포트에 적는다.**</u>
> 
> 
> 빈칸(NaN)이 있으면 모델 학습에서 오류가 나기 때문이다.
> 

| 상황 | 대체값 |
| --- | --- |
| 송신 패킷이 하나도 없음 | 송신 위치 평균·표준편차 = 0 |
| 값이 1개뿐이라 표준편차를 못 구함 | 0 |
| 간격을 구할 패킷이 2개 미만 (예: 송신 1개) | 해당 간격 통계 = 0 |
| 지속 시간이 0 | 상대 도착 시점 = 0, 1초 구간은 1개(전체 패킷 수)로 봄 |
| 0보다 큰 간격이 없음 | 양의 간격 통계 = 0 |
