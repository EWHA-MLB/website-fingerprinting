# SVM · Extra Credit (TrafficSliver 분할 트래픽) 결과

담당: 김가영 (SVM) · 노트북 `extra_credit/MLB_SVM_extra.ipynb` · 결과 `results/svm/extra_credit/`

## 요약

- **조건 A (메인 모델 그대로)**: 방문 단위 정확도 **0.011**. 95개 사이트를 무작위로 고르는 수준(1/95 ≈ 0.0105)이다. 분할 방어가 기존 SVM을 사실상 완전히 막았다.
- **조건 B (split으로 학습)**: **0.133**(포함) / **0.145**(제외). 다시 학습하면 일부 회복되지만 메인 정확도(0.852)에는 크게 못 미친다.
- **조건 C (메인 + split)**: **0.150** / **0.154**. B보다 1.0~1.7%p 높다.
- **제외 버전이 포함 버전보다 일관되게 조금 높다**(B +1.2%p, C +0.4%p).
- B·C는 시간 제약으로 **학습 방문 30%만 샘플링**했다. 같은 B 포함 조건을 전체 데이터로 학습하면 0.196이므로, 30% 결과의 절대값은 실제보다 낮다. 조건끼리는 같은 30%라서 비교할 수 있다.

## 1. 실험 설정

규칙 페이지(모델팀 실험 규칙)를 따랐다.

| 항목 | 설정 |
| --- | --- |
| 과제 | Closed-world 95 클래스 (Open-world 이진은 시간 문제로 생략) |
| 입력 | `full_trim0`의 split CSV, 특징 110개(`g1_`~`g6_`). join은 기본 조건에서 제외 |

| 하이퍼파라미터 | 메인 best 고정: 110개 C=2⁷, γ=2⁻⁶ / g1+g6 53개 C=2¹⁴, γ=2⁻² |
| 전처리 | 메인과 같음. g1~g5 `log1p` → 상수 특징 제거 → 표준화 → RBF SVC. 각 조건의 학습 데이터에서만 fit |
| 확률 | `CalibratedClassifierCV(method="sigmoid", ensemble=False)`에 분할 파일의 `fold`를 cv로 넘김 (방문 단위 5-fold) |
| 방문 단위 판정 | 방문의 split 확률 평균 → argmax. 제외 버전은 남은 split만 평균 |

**조건 A·C의 메인 기록 대응.** mon은 extra `(p, s)` = 메인 `(page p×10 + s//20, sample s%20)`, unmon은 같은 번호로 대응시켰다. 점검한 내용은 다음과 같다.
- 메인 train 기록은 extra에서도 모두 train이다. 그래서 A·C 학습에 extra test 방문이 들어가지 않는다.
- 메인에서는 test인데 extra에서는 train인 unmon 방문이 107개 있다. extra test 평가에는 영향이 없다.

**빈 행 제외 버전.** 데이터팀의 `*_without_zero.csv.gz`를 따로 받지 않았다. 포함 버전 CSV에서 `status == "empty"` 행을 걸러 만들었다. 남은 행은 172,085개로 `validation_without_zero.json`의 보고값과 같다. 빈 행 17,915개는 특징이 모두 0인 행과 정확히 일치했다.

### 학습 방문 샘플링 (규칙 5장)

- 전체 데이터로 B 포함(학습 76,000행)을 돌렸더니 **학습 65분 + 예측 16분 = 81분**이 걸렸다. 규칙의 1시간 기준을 넘는다.
- 그래서 B·C는 **학습 방문 30%만 샘플링**했다. 라벨별로 층화했고, 한 방문의 split 5개와 대응하는 메인 기록은 함께 뽑았다(seed 42).
- A는 메인 train 전체(15,200행)를 썼다.
- 전체 데이터로 돌린 B 포함 결과는 `condition = B_full100` 참고 행으로 남겼다.

## 3. 해석

1. **분할 방어는 기존 모델에 매우 효과적이다.** A는 무작위 수준이다. 메인 기록 전체로 학습한 모델이, 한 경로에서 관찰한 일부 트래픽(split)에서는 사이트 패턴을 전혀 찾지 못한다.
2. **split으로 다시 학습해도 회복은 제한적이다.** B는 방문 단위 0.13~0.20 수준이다(무작위의 약 13~19배). 그러나 메인 0.85에는 크게 못 미친다. B 전체 데이터 모델은 학습 76,000행 중 **75,684개(99.6%)가 support vector**였다. 이 특징 공간에서는 사이트끼리 거의 분리되지 않는다는 신호다.
3. **혼합 학습(C)은 B보다 조금 낫다.** 포함 버전 +1.7%p, 제외 버전 +1.0%p다. 메인 기록이 추가 학습 데이터 역할을 하지만 효과는 작다.
4. **빈 행은 제외하는 편이 낫다.** 제외 버전이 B·C 모두에서 조금 높다. 빈 split은 모든 사이트에서 같은 0 벡터라 사이트 정보가 없다. 규칙 페이지의 예상 방침(학습은 제외 버전, 평가는 방문 단위)과 맞는다.
5. **방문 단위 판정이 행 단위보다 약 2배 높다.** B 포함 기준 행 0.065 → 방문 0.133이다. 한 방문의 split 5개를 모으면 정보가 늘어난다. 이는 공격자가 여러 경로를 함께 관찰할 수 있다면 방어 효과가 약해진다는 뜻이기도 하다.
6. **30% 샘플링의 영향.** B 포함이 전체 데이터에서는 0.196, 30%에서는 0.133이다(−6.3%p). 학습 데이터가 늘수록 성능이 계속 오르는 상태여서, 30% 결과의 절대값은 실제보다 낮게 나왔다고 보는 게 맞다. 다만 B·C와 두 버전은 같은 비율로 학습했으므로 조건 사이의 비교에는 쓸 수 있다.

## 4. 규칙과 다르게 한 점 (`note` 열에도 기록)

- B·C는 학습 방문 30%를 샘플링했다 (규칙 5장의 1시간 초과 조항).
- 확률은 `probability=True` 대신, 방문 단위 fold로 보정하는 `CalibratedClassifierCV`로 만들었다. `probability=True`의 내부 보정은 행 단위 5-fold라 규칙의 "행 단위 KFold 금지"와 맞지 않는다.
- 제외 버전은 포함 버전 CSV를 걸러 만들었다(행 수가 데이터팀 보고값과 일치).
- g1+g6 53개 결과의 확률 파일 이름 끝에 `_g1g6_53`을 붙였다 (110개 파일과 구분하기 위해).
- Open-world 이진(선택)은 시간 제약으로 생략했다.
- 실행 환경은 Colab이 아니라 로컬 PC다 (공유 드라이브를 마운트할 수 없어서).
